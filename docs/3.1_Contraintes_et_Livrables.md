# 3. Spécifications fonctionnelles

## 3.1 Contraintes du projet et livrables attendus

### 3.1.1 Contraintes fonctionnelles

Spotly doit permettre à un voyageur de découvrir rapidement des expériences locales correspondant à sa situation.

L'application devra notamment prendre en compte :

- la localisation de l'utilisateur ;
- la proximité des spots ;
- le temps disponible de l'utilisateur ;
- les centres d'intérêt et préférences ;
- les informations associées aux spots ;
- les interactions de la communauté.

La fonctionnalité principale devra rester simple et rapide à utiliser afin de ne pas imposer à l'utilisateur de nombreuses étapes avant de trouver une expérience pertinente.

### 3.1.2 Contraintes techniques

Le projet devra respecter les choix techniques définis dans le cahier des charges :

- une application web responsive et **mobile-first** ;
- une séparation entre le frontend, le backend et la base de données ;
- une API REST pour les échanges entre le frontend et le backend ;
- une base de données relationnelle ;
- une gestion sécurisée des comptes utilisateurs ;
- une gestion des données géographiques nécessaires à la découverte des spots ;
- une architecture permettant de faire évoluer l'application.

Les technologies et leurs versions seront détaillées dans la partie **Spécifications techniques**.

### 3.1.3 Contraintes d'éco-conception

L'éco-conception constitue une contrainte importante du projet.

Spotly devra notamment chercher à limiter les ressources consommées par l'application en :

- optimisant le poids des images ;
- utilisant des formats adaptés tels que WebP lorsque cela est pertinent ;
- évitant le chargement inutile de ressources ;
- mettant en place du chargement différé (*lazy loading*) lorsque cela est pertinent ;
- limitant le nombre de dépendances ;
- optimisant les requêtes vers l'API et la base de données ;
- mettant en place de la pagination lorsque nécessaire ;
- limitant les animations et effets inutiles ;
- favorisant la mise en cache des données lorsque cela est pertinent.

Ces choix seront détaillés et justifiés dans la partie consacrée aux spécifications techniques et à l'éco-conception.

### 3.1.4 Contraintes d'accessibilité

L'application devra être conçue de manière à être utilisable par le plus grand nombre.

Une attention particulière sera portée notamment :

- à la lisibilité des contenus ;
- à la navigation au clavier ;
- à la structure sémantique des pages ;
- aux textes alternatifs des images ;
- aux contrastes ;
- aux formulaires et messages d'erreur ;
- à la compatibilité avec les technologies d'assistance lorsque cela est pertinent.

### 3.1.5 Contraintes de sécurité et de protection des données

Spotly devra prendre en compte les principes de sécurité applicables à une application web.

Les principaux points concernés seront :

- sécurisation de l'authentification ;
- protection des mots de passe ;
- validation des données reçues par l'API ;
- contrôle des autorisations ;
- protection contre les entrées malveillantes ;
- limitation de l'exposition des données personnelles ;
- gestion appropriée des données de localisation ;
- prise en compte des principes du RGPD.

### 3.1.6 Livrables attendus

La conception et le développement de Spotly donneront lieu à plusieurs livrables :

- cahier des charges ;
- spécifications fonctionnelles ;
- maquettes des interfaces ;
- parcours utilisateurs ;
- diagramme de cas d'utilisation ;
- diagrammes de séquence ;
- modèle conceptuel de données ;
- modèle physique de la base de données ;
- scripts ou migrations de base de données ;
- spécifications techniques ;
- application frontend ;
- API backend ;
- base de données ;
- tests ;
- documentation du projet.

Les éléments réellement produits seront présentés dans les différentes parties du dossier CDA.
